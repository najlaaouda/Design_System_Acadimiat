# الفلترة: النمط المعتمد فوق الجداول — نمط

> أن يضيّق المستخدم قائمة طويلة إلى ما يبحث عنه، وأن يرى في كل لحظة **ما المطبَّق الآن وكيف يلغيه** (UX-22)، وأثر ما فعل (UX-11).

## 1. متى تستخدمه

> **الحالة:** مطبَّق في `/admin/blog/articles` (2026-09-10) — أوّل متبنٍّ. ثم التصنيفات والوسوم وبقية جداول اللوحة. انظر [خطة التحويل](#خطة-التحويل).
>
> **اليوم (قيس 2026-09-26):** `<app-filter-panel>` في 8 شاشات — المقالات · الدورات · الطلبات · الكوبونات · السلات المتروكة · الاستطلاعات · سجل المسحوبات (`finance-history`) · مقارنة المبيعات. و`<app-filter-bar>` في 10: الثماني نفسها وتقريرا الطلبات (`product-orders` و`coupon-orders`). و`<app-filter-chip>` في شاشة واحدة (`product-orders`). والتصنيفات والوسوم لم تُنقل بعد.

## 2. متى لا تستخدمه

`app-filter-chip` يبقى للقليل: جدول بخاصية واحدة لا يحتاج لوحة. ومتى وُجدت خاصيتان فأكثر فالنمط أعلاه.

## 4. التشريح

```text
المقالات                                   [مقال جديد] [إنشاء بالذكاء الاصطناعي]
┌──────────────────────────────────────────────────────────────────────────┐
│ [⌕ البحث بعنوان المقال  ] [⧩ فلترة النتائج ②]   [⇅ الأكثر مشاهدة ▾] [تصدير] │  ① الشريط
│ 12 مقالًا   الفلاتر المطبقة: الحالة: منشور ⊗  التصنيف: التسويق ⊗  مسح الفلاتر │  ② المطبَّق
├──────────────────────────────────────────────────────────────────────────┤
│ الجدول                                                                   │
```

1. **الشريط** — `app-table-toolbar`: البحث ثم «فلترة النتائج» في طرف البداية، والترتيب والتصدير في طرف النهاية. **الفلتر بجوار البحث في كل عرض وكل متصفح** (قرار المنتج 2026-09-24). في فايرفوكس كان ينزل تحت البحث على الشاشة الواسعة: المتصفح يقيس المجموعة من محتوى الحقل لا من أساسه (`flex-basis`)، فعرض الحقل صريح في `inline-size` أيضًا. و≤ 768 يملأ الحقل ما يتركه الفلتر في سطرهما ولا ينزل عن نصف السطر — كان يأخذ السطر وحده. و≤ 640 يصير الزرّ أيقونة الفلتر وشارة العدد وحدهما، والنصّ باقٍ اسمًا له. حقلان معًا (الفترة والبحث) أو رقاقة أعرض من نصف السطر يلتفّان سطرًا ولا يسحقان الحقل.
2. **المطبَّق** — `app-filter-bar`: عدد النتائج أوّلًا، ثم رقائق الخصائص المطبَّقة و«مسح الفلاتر». يظهر مع شرط مطبَّق وحده.

البحث **لا يُكرَّر رقاقة**: ظاهر في حقله، ورقاقةٌ ثانية تقول ما يقوله الحقل فوقها.

## 5. الأنواع

> النمط بشكل واحد على الشاشة الواسعة: لوحة بعمودين (§7 «لوحة الفلترة»)، وعلى الجوال (≤ 640px) الدرج بأقسام متتالية (§8 «الجوال»)؛ و`app-filter-chip` لجدول بخاصية واحدة (§2).

## 6. شجرة القرار

### القرار — ولماذا

اعتُمد بعد إلهام من Mobbin (Notion، Twenty، Base44، Mercury، Hashnode، Substack، Pinterest) ومقارنةٍ بفلتر المقالات القائم.

| | قبل: صفّ رقائق | الآن |
|---|---|---|
| الفلاتر | خمس رقائق ظاهرة دائمًا، مطبَّقة أو لا | زرّ «فلترة النتائج» واحد بعدّاد، يفتح لوحة بعمودين |
| المطبَّق | داخل نصّ كل رقاقة | رقائق تحت الشريط لكل فلتر مطبَّق وحده، بـ × لكلٍّ و«مسح الفلاتر» |
| الحالة | رقاقة بين الرقائق | **أوّل خصائص اللوحة** — مدخل واحد للفلترة كلّها ([الحالة](#الحالة)) |
| الترتيب | رقاقة تتلوّن كفلتر مطبَّق | زرّ مستقل — الترتيب لا يُخفي صفًّا فليس فلترًا |
| عدد النتائج | لا شيء | «12 مقالًا» أوّل صفّ الرقائق |
| «لا نتائج» | زرّ واحد يمسح كل شيء | زرّ إزالة **لكل** فلتر مطبَّق (نمط Pinterest)، و«مسح الكل» |

**لم يُعتمد الآن:** حفظ الفلترة في الرابط، والعروض المحفوظة.

### لماذا لوحة لا `<app-menu>`؟

القائمة تُغلق عند أول نقرة على زرّ داخلها — صحيح للأوامر، وقاتل هنا: التنقّل بين الخصائص نقرٌ على أزرار. واللوحة `role="dialog"` غير مشروط، بلا خلفية معتمة: الخلفية الشفّافة تبتلع أوّل نقرة خارجها.

## 7. القواعد

### الحالة

**أوّل خصائص اللوحة** — «منشور · غير منشور · مسودة» — لا مفتاحًا فوق الجدول.

> **قرار 2026-09-10:** جُرّبت الحالة مفتاحًا مقطّعًا ظاهرًا فوق الجدول («الكل · منشور · غير منشور»، نمط Hashnode وSubstack)، ثم طلب المستخدم نقلها إلى اللوحة: مدخلٌ واحد للفلترة كلّها، ولا شريط ثانٍ فوق الجدول. ومظهر `appRadioGroup appearance="segmented"` مستخدمه اليوم فلتر حالة الربط في صفحة التطبيقات — خاصية واحدة فوق بطاقات، لا جدول ([`checkbox-radio-switch.md`](../atoms/checkbox-radio-switch.md#مظهر-المفتاح-المقطّع--appearancesegmented)).

* **«مسودة» معطّلة بشارة «قريبًا»** (`FilterPanelOption.disabled` + `hint`) — الخادم لا يفرّق بينها وبين «غير منشور» بعد ([`REQ-010`](../../BACKEND-REQUIREMENTS.md)). تُرسم ولا تُختار: المستخدم يعرف أنها قادمة، ولا يحصل على نتيجة تخلط النوعين. ولا تُرسم قيمةٌ تعمل على غير ما تقول.
* «غير منشور» اليوم يعيد الاثنين معًا (`isPublishedBlogs: false`) — وهو وصفٌ صادق لهما.
* **العدّاد لكل حالة** («منشور 12») حين يرسله الخادم وحده — لا يُحسب من الصفحة المحمَّلة ([`REQ-010`](../../BACKEND-REQUIREMENTS.md)).

### لوحة الفلترة — `<app-filter-panel>`

```html
<app-filter-panel
  toolbar-filters
  [facets]="facets"
  [selected]="selection"
  (selectedChange)="onFilterChange($event)"
  (cleared)="clearPanelFilters()"
/>
```

```ts
readonly facets: FilterFacet[] = [
  { key: 'status',   label: 'الحالة',  options: [
    { value: 'published',   label: 'منشور' },
    { value: 'unpublished', label: 'غير منشور' },
    { value: 'draft',       label: 'مسودة', disabled: true, hint: 'قريبًا' },
  ] },
  { key: 'author',   label: 'الكاتب',  options: authors },
  { key: 'category', label: 'التصنيف', options: categories },
  { key: 'tag',      label: 'الوسم',   options: tags },
];
selection: Record<string, string | null> = { status: null, author: null, category: '10', tag: null };
```

| المُدخل | النوع | الافتراضي | |
|---|---|---|---|
| `facets` | `FilterFacet[]` | `[]` | الخصائص وقيمها (`FilterPanelOption`: `value` · `label` · `count?` · `disabled?` · `hint?`). خاصية بلا قيم لا تُرسم، ولا زرّ إن خلت كلّها |
| `selected` | `Record<key, string \| null>` | `{}` | القيمة المختارة لكل خاصية. غيابها أو `null` = «الكل» |
| `label` | `string` | `'فلترة النتائج'` | نصّ الزرّ — يقول ما يُفلتَر لا الفعل وحده (قرار 2026-09-10؛ كان «فلترة») |
| `heading` | `string` | `'الفلاتر'` | اسم اللوحة لقارئ الشاشة وعنوان الدرج |
| `disabled` | `boolean` | `false` | |

| المُخرج | يحمل | |
|---|---|---|
| `selectedChange` | `{ key, value }` | `value: null` = عادت الخاصية إلى «الكل» |
| `cleared` | — | «مسح الفلاتر» |

#### السلوك

* **الزرّ** `dsButton variant="secondary"` بأيقونة `essential/filter`. عدد الخصائص المفلترة شارةٌ بلون الفعل الأساسي داخله — الزرّ نفسه لا يتلوّن. والشارة مخفية عن قارئ الشاشة، والاسم يحملها: «فلترة النتائج، المطبق منها 2».
* **العمود الأول** تبويبات عمودية (`tablist`): تبدّل **أيّ قيم تُعرض** لا أيّ صفوف — وجوه اللوحة الواحدة، فلا تخالف «التبويب ليس فلترًا». وتحت اسم كل خاصية قيمتها المختارة، فالمطبَّق يُقرأ بلا تنقّل.
* **العمود الثاني** أزرار اختيار (`app-radio`): الخادم يقبل قيمة واحدة لكل خاصية. «الكل» أوّلها. **ومربّعات الاختيار المتعدد** طلبها المستخدم (2026-09-10) وتنتظر الخادم ([`REQ-012`](../../BACKEND-REQUIREMENTS.md)) — واختار أن يبقى كل شيء اختيارًا واحدًا حتى يُنفَّذ، لا مربّعًا يَعِد بتعدّد لا يقع.
* **قيمة معطّلة بتلميح** (`disabled` + `hint`): قيمة معروفة لا يفلتر بها الخادم بعد — «مسودة». تُرسم باهتة بشارة محايدة «قريبًا» داخل تسميتها، فيُقرأ السبب مع الاسم.
* **الاختيار يسري فورًا** — لا زرّ «تطبيق». الرقائق وعدد النتائج تحت الشريط تقول أثره في الحال.
* **فوق ثماني قيم** يظهر حقل بحث في عمودها بتطبيع `app-search-field` نفسه («احمد» تجد «أحمد»). و«الكل» تغيب أثناء البحث، وبحث بلا مطابقة يقول «لا توجد نتائج مطابقة».
* **تفتح على الخاصية الأولى** دائمًا: موضع ثابت يُتعلَّم مرة.
* **الإغلاق:** Escape (وداخل حقل البحث تمسح النصّ أوّلًا)، والنقر خارجها، وخروج التركيز منها بـ Tab. والتركيز يعود إلى الزرّ — إلا حين يغلقها نقرٌ في مكان آخر، فيبقى حيث نقر المستخدم.

| عمود القيم | 264px | `--ds-filter-panel-options-width` |
| أقصى ارتفاع | `min(400px, 70vh)` — القيم تتمرّر في عمودها وحده | `--ds-filter-panel-max-block-size` |

| القيمة المختارة تحت الاسم | 12px | `--ds-color-text-muted` |

حشوة عمود القيم **عليه لا على اللوحة**: `overflow-y` يقصّ ما خرج عن صندوقه، وحلقة تركيز حقل البحث تخرج 3px — فتعيش داخل الحشوة (الدرس نفسه في [`modal-drawer.md`](../organisms/modal-drawer.md)).

عرض العمودين في `inline-size` **مع** `flex-basis`، لا في الأساس وحده (بلاغ المنتج 2026-09-24، «خيارات الفلتر جزء منها مخفي» في كل الصفحات): فايرفوكس يقيس عرض اللوحة العائمة من نصوص العمودين لا من أساسهما، فخرجت 371px والعمودان 440 — وقُصّ من عمود القيم 70px على جانبه («مخفي من أكاديميات بلس» بلا آخره). كروم سليم فلم تره لقطاته. القاعدة لكل لوحة عائمة بأعمدة ثابتة: العرض صريح في `inline-size`.

### المطبَّق — `<app-filter-bar>`

رقاقة لكل خاصية مطبَّقة («التصنيف: التسويق ⊗»)، و«مسح الفلاتر» مع فلتر مطبَّق وحده، وعدد النتائج بـ `aria-live="polite"`. مواصفته في [`page-structure.md`](./page-structure.md#filter-bar).

```html
<app-filter-bar
  table-toolbar
  appearance="inline"
  ariaLabel="الفلاتر المطبقة"
  [applied]="appliedFilters"
  [resultCount]="resultCount"
  [resultNoun]="{ singular: 'مقال', dual: 'مقالان', plural: 'مقالات', accusative: 'مقالًا' }"
  (removed)="removeFacet($event)"
  (cleared)="clearPanelFilters()"
/>
```

| المُدخل | النوع | الافتراضي | |
|---|---|---|---|
| `appearance` | `'card' \| 'inline'` | `'card'` | `card` بطاقة بمنافذ `[filter-search]` والمحتوى الافتراضي (الحقول) و`[filter-actions]`، والمطبَّق تحتها؛ `inline` الصفّ وحده |
| `applied` | `readonly AppliedFilter[]` — `{ key, label, value }` | `[]` | فارغة: لا رقائق ولا «مسح الفلاتر» |
| `resultCount` | `number \| null` | `null` | `null` يخفي العدد. إخفاؤه صفرًا وأثناء التحميل على المستهلك: يمرّر `null` |
| `resultNoun` | `SelectionNoun \| null` | `null` | بلا قيمة: «نتيجة / نتيجتان / نتائج» |
| `ariaLabel` | `string` | `'فلاتر'` | اسم `<section>` لقارئ الشاشة |

| المُخرج | يحمل | |
|---|---|---|
| `removed` | `string` — `key` الرقاقة | زرّ الإزالة في الرقاقة |
| `cleared` | — | «مسح الفلاتر» |

`formatResultCount(count, noun)` مصدَّرة من الملف نفسه: 0 ← «لا مقالات» · 1 ← «1 مقال» · 2 ← «مقالان» · 3–10 ← «3 مقالات» · فوق 10 ← «12 مقالًا». وعلى الجوال (حتى 768) تتكدّس حقول مظهر `card` عمودًا بعرض كامل. (وُثّق 2026-09-26 من الكود)

* **`appearance="inline"`** (2026-09-10): صفّ المطبَّق والعدد وحده، يُسقَط في منفذ `table-toolbar` بعد `app-table-toolbar` فيجلس تحته داخل قشرة الجدول، بخلفية الشريط وحدّه — سطرٌ ثانٍ من أدوات الجدول لا بطاقة داخل بطاقته. بلا مطبَّق ولا عدد لا يأخذ ارتفاعًا، والمنطقة الحيّة باقية فيه فارغة: منطقةٌ تُدرَج مع نصّها لا يعلنها قارئ الشاشة.
* **`resultNoun`** — المعدود بصيغه الأربع (`SelectionNoun` من `app-table-selection-bar`)، والناتج من `formatResultCount`: «1 مقال» · «مقالان» · «3 مقالات» · «12 مقالًا». بلا قيمة: «نتيجة / نتيجتان / نتائج». كان يطبع «3 نتيجة».
* **العدد أوّل السطر** (طرف البداية — يمينًا في العربية؛ قرار 2026-09-10، كان في آخره) بوزن متوسط ولون النصّ الأساسي: جواب «ماذا فعلت الفلترة؟» يُقرأ قبل ما أنتجه. ومع شرط مطبَّق وحده، ولا يُعرض صفرًا (حالة «لا نتائج» تقوله) ولا أثناء التحميل (عددٌ قديم فوق نتيجة جديدة).
* **الرقائق لخصائص اللوحة — والحالة منها.** البحث ظاهر في حقله فلا رقاقة له، و«مسح الفلاتر» لا يمسحه.
* **الرقاقة بيضاء بحدّ محايد** (`surface-default` · `border-default` · نصّ `text-primary`؛ قرار 2026-09-10، كانت بلون العلامة الخفيف): تقول ما طُبِّق ولا تنافس الفعل الأساسي على لونه — وشارة عدّاد «فلترة النتائج» وحدها بلون العلامة.
* زرّ إزالة الرقاقة 24px مرسومة بأيقونة `essential/close-circle`، وعلى اللمس يمتدّ هدفه إلى 44px بطبقة شفّافة لا تزيح شيئًا.
* في الكود: الرقاقة كبسولة (`--ds-radius-pill`) بخط 12، حشوتها 12 من البداية و4 من النهاية، والتسمية `text-muted` والقيمة `medium`. وزرّ الإزالة عند المرور `surface-sunken` ونصّ `text-primary`. و«مسح الفلاتر» زرّ نصّي 12 `medium` بلون `text-brand`، ارتفاعه الأدنى 36 (`--ds-control-height-sm`)، ومروره `surface-hover`. وسطر «الفلاتر المطبقة:» 12 `text-muted`. (وُثّق 2026-09-26 من الكود)

### رقاقة الفلتر — `<app-filter-chip>`

لجدول بخاصية واحدة (§2). رقاقة تفتح لوحة `listbox` بموضع `FloatingPanel`، ونصّها يحمل القيمة: «الحالة: فعال» · «الحالة: فعال +2» · «الحالة: الكل (48)».

| المُدخل | النوع | الافتراضي | |
|---|---|---|---|
| `label` | `string` | — | **مطلوب**. اسم الخاصية |
| `options` | `readonly FilterChipOption[]` — `{ value, label, count? }` | `[]` | `count: null` لا يُعرض |
| `selected` | `readonly string[]` | `[]` | مصفوفة حتى في الأحادي |
| `multiple` | `boolean` | `false` | متعدد بمربّعات `app-checkbox` واللوحة تبقى مفتوحة؛ الأحادي يُغلق بالاختيار، والضغط على المختار يلغيه |
| `disabled` | `boolean` | `false` | |
| `emptyLabel` | `string` | `'الكل'` | |
| `totalCount` | `number \| null` | `null` | بين قوسين بجوار «الكل» |

المُخرج: `selectedChange` (`readonly string[]`). ↓ يفتح اللوحة، وEscape يغلقها ويعيد التركيز إلى الرقاقة.

الشكل: ارتفاع أدنى 36، استدارة 8، حدّ `border-default`، 14 `medium`؛ والمطبَّقة بخلفية `--ds-color-brand-bg` وحدّ `--ds-color-brand-border` ونصّ `text-brand`؛ واللوحة 220–320 عرضًا و`min(320px, 60vh)` ارتفاعًا، استدارة 8 وظلّ `elevation-2`. (وُثّق 2026-09-26 من الكود)

* ⚠️ تعارض (2026-09-26): المواصفة ([`iconography.md`](../foundations/iconography.md) و`CLAUDE.md` الجذر: كل أيقونة من `src/icons/` عبر `<ds-icon>`) · الكود: سهم الرقاقة محرف ▾ (`&#9662;`) بشفافية 0.7، وعلامة الاختيار في الأحادي محرف ✓ — لا `arrow/arrow-down-02` ولا أيقونة من المجموعة.

### الترتيب

زرّ مستقل في طرف النهاية — `dsButton variant="secondary"` بأيقونة `essential/sort` ونصّ الترتيب الحالي، يفتح `<app-menu>`:

```html
<button dsButton variant="secondary" [appMenuTriggerFor]="sortMenu" [attr.aria-label]="'الترتيب: ' + sortLabel">
  <ds-icon button-icon name="essential/sort" size="sm" />
  {{ sortLabel }}
  <ds-icon button-icon-end name="arrow/arrow-down-02" size="sm" />
</button>
```

* **ليس فلترًا:** لا يُخفي صفًّا، فلا يُحسب في عدّاد «فلترة» ولا يصنع رقاقة ولا يحوّل الشاشة إلى «لا نتائج».
* الاسم يبدأ بالنصّ الظاهر ويسبقه «الترتيب:» (WCAG 2.5.3).
* القائمة تُغلق بالاختيار — والترتيب قيمة واحدة، فهذا صحيح هنا بخلاف اللوحة.

### «لا نتائج»

`<app-empty-state variant="no-results">` داخل بنية الجدول، والشريط والرقائق باقية فوقه — هي أسباب الخلوّ وطريق الخروج منه.

الأفعال **زرّ لكل ما يضيّق القائمة الآن**، لا زرّ واحد يمسح كل شيء:

```text
             لا توجد مقالات مطابقة
     جرب إزالة أحد الفلاتر أو تغيير كلمة البحث.

 [⊗ إزالة البحث] [⊗ إزالة فلتر الحالة] [⊗ إزالة فلتر التصنيف]  مسح الكل
```

من ضيّق بثلاثة شروط يعرف غالبًا أيّها الزائد؛ «مسح الكل» وحده يرميه إلى القائمة كاملة ليعيد بناء الاثنين الباقيين. و«مسح الكل» يظهر مع شرطين فأكثر، ويمسح كل شرط — البحث والحالة والخصائص — بخلاف «مسح الفلاتر» في الرقائق.

الأزرار `secondary` بمقاس `sm` وأيقونة `essential/close-circle`، و«مسح الكل» `tertiary` بأيقونة `essential/filter-remove`. تُلفّ في حاوٍ واحد يحمل `empty-actions`: الإسقاط لا يطابق عناصر داخل `@for`/`@if` بسمتها.

### خلفية الخادم

الفلترة كلّها **خادمية**: كل خاصية معامل يقبله الخادم، والعدد من `total` في ردّه. قبل إضافة خاصية يُسأل: **هل يقبل الخادم هذا المعامل؟** — تصفية الصفحة المحمَّلة وحدها فوق جدول مرقَّم من الخادم كذبٌ يفضحه العدّاد (المرجع: `d:\Acadimiat\Design-system-Acadimiate\components\table-filter.md`).

وما لا يرسله الخادم لا يُرسم ولا يُشتقّ:

| الحاجة | الحالة | الحلّ المؤقّت |
|---|---|---|
| «مسودة» و«غير منشور» حالتان منفصلتان | [`REQ-010`](../../BACKEND-REQUIREMENTS.md) | «مسودة» في اللوحة معطّلة بشارة «قريبًا»، و«غير منشور» يعيد الاثنين |
| عدّاد لكل حالة | [`REQ-010`](../../BACKEND-REQUIREMENTS.md) | بلا عدّاد؛ عدد النتائج الإجمالي وحده |
| أكثر من قيمة للخاصية الواحدة (مربّعات) | [`REQ-012`](../../BACKEND-REQUIREMENTS.md) | زرّ اختيار واحد لكل خاصية — بقرار المستخدم حتى يُنفَّذ |

### خطة التحويل

1. ✅ **المكوّنان** (2026-09-10): `app-filter-panel`، ومظهر `segmented` لـ `appRadioGroup`، و`unpublished` في `STATUS_MAP`.
2. ✅ **المقالات** `/admin/blog/articles` (2026-09-10): اللوحة بالحالة أوّلًا، والترتيب المستقل، والمطبَّق تحت الشريط بمظهر `app-filter-bar` المضمَّن وتمييز عدده، و«لا نتائج» بزرّ لكل شرط، والدرج على الجوال. وحالة «غير منشور» في العمود والتصدير، والكاتب في سطر واحد.
   ⚠️ **سؤال مفتوح — الترتيب:** الصفحة الأولى تُعاد ترتيبها على الواجهة بـ `order` (الترتيب اليدوي) بعد وصولها، فـ«الأكثر مشاهدة» يحدّد **أيّ** خمسة مقالات تصل لا ترتيبها، و«تحميل المزيد» يُلحق بلا إعادة ترتيب. سلوكٌ قائم قبل الترحيل لم يُغيَّر: تصحيحه يحتاج أن نعرف ما يعيده الخادم حين يغيب `moreVisiting` — هل هو الترتيب اليدوي؟ وعندها يصير خيار «الترتيب اليدوي» ثالثًا، والسحب يُتاح فيه وحده.
3. ⏳ اعتماد النمط، ثم التصنيفات والوسوم وبقية جداول اللوحة، كلٌّ بمراجعة مستقلة. (قيس 2026-09-26: اللوحة في 8 شاشات — انظر §1 — والتصنيفات والوسوم لم تُنقل.)

## 8. RTL والاستجابة

### RTL

* اللوحة: عمود الخصائص في جهة البداية (يمينًا في العربية)، والحدّ بينهما `border-inline-end`، و`FloatingPanel` (`shared/ui/overlay`) يقلب `start/end` في موضع اللوحة — بلا مكتبة. والأسهم ↑↓ بين الخصائص فلا تنعكس.
* الدرج يخرج من جهة البداية.
* كل المسافات منطقية.

### الجوال (≤ 640px)

الزرّ بجوار حقل البحث، أيقونة `essential/filter` وشارة العدد وحدهما (`.ds-filter-panel-trigger__label` مخفيّ بصريًّا، والغلاف `.ds-button__label` يذوب فلا يترك فجوة ثانية). والزرّ نفسه يفتح [`<app-drawer>`](../organisms/modal-drawer.md#drawer) بعرض الشاشة: الخصائص **أقسام متتالية** بعناوينها، وفي الذيل «مسح الفلاتر» و«عرض النتائج» بعرض كامل. عمودان على 400px يسحقان كليهما. والاختيار يسري فورًا هنا أيضًا — «عرض النتائج» يُغلق الدرج ليرى المستخدم ما تحته. واللوحة تقفل تمرير الخلفية وتعيد التركيز إلى الزرّ، وهما مسؤولية المستدعي في الدرج.

640 هي نقطة الدرج نفسه، لا نقطة جديدة.

> [!WARNING]
> **اللوحة والدرج يرسمان القالب نفسه — فلا يتشاركان اسم مجموعة** (خلل أُصلح 2026-09-11)
>
> كان اختيار قيمة في اللوحة يحتاج نقرتين: الأولى تُظهر حلقة التركيز وحدها، والثانية تختار. السبب أن المحتوى المُسقَط في `<app-drawer>` يُنشأ ولو كان الدرج مغلقًا، فكانت نسخة مخفية من كل خيار حيّة بجوار خيارات اللوحة **وباسم مجموعتها نفسه**. و`RadioRegistry` يُلغي كل خيار يشارك اسم ما اختير للتوّ — فتُحدَّث النسخة المخفية بعد الظاهرة في دورة الرسم نفسها وتُلغي اختيارها.
>
> الإصلاح اثنان: اسم مجموعة لكل سطح (`…-panel-status` · `…-drawer-status`)، وأقسام الدرج تُنشأ والدرج مفتوح وحده (`@if (drawerOpen)`). واختبارا «نقرة واحدة على اسم القيمة» في اللوحة والدرج يحرسان ذلك — بالنقر على الـ `label` كما يفعل المستخدم، لا على العنصر الأصلي المخفي.

## 9. إمكانية الوصول

| المتطلب | كيف |
|---|---|
| الزرّ | `aria-haspopup="dialog"` و`aria-expanded`، والعدد في اسمه لا في الشارة وحدها |
| اللوحة | `role="dialog"` باسم، و`tablist` عمودي بـ `aria-selected` و`aria-controls` وتركيز متنقّل (`tabindex` 0/-1) |
| لوحة المفاتيح | ↑↓ و Home/End بين الخصائص، Tab إلى القيم، الأسهم بين القيم، Escape تُغلق |
| التركيز عند الفتح | الخاصية النشطة |
| التركيز عند الإغلاق | يعود إلى الزرّ |
| عدد النتائج | `aria-live="polite"` في `app-filter-bar` — لا يقاطع الكتابة |
| الخاصية النشطة | خلفية ولون **ووزن** — لا اللون وحده |

## 11. مثال

> الأمثلة مع أجزائها في §7: لوحة الفلترة (`<app-filter-panel>` وخصائصها `facets`)، والمطبَّق (`<app-filter-bar appearance="inline">`)، وزرّ الترتيب؛ والشريط كاملًا مرسوم في §4.

المثال المركّب من [`articles.component.html`](../../../src/app/views/admin/blog/articles/articles.component.html) مختصرًا — الشريط، ثم المطبَّق، ثم الجدول و«لا نتائج» داخله:

```html
<app-table caption="قائمة المقالات" [bordered]="true">
  <app-table-toolbar table-toolbar>
    <app-search-field toolbar-filters label="البحث في المقالات" [hideLabel]="true"
      placeholder="البحث بعنوان المقال" [(ngModel)]="blogName" (searchChange)="onSearch($event)" />
    <app-filter-panel toolbar-filters [facets]="facets" [selected]="selection"
      (selectedChange)="onFacetChange($event)" (cleared)="clearPanelFilters()" />

    <ng-container toolbar-actions>
      <button dsButton type="button" variant="secondary" [appMenuTriggerFor]="sortMenu"
        [attr.aria-label]="'الترتيب: ' + sortLabel">
        <ds-icon button-icon name="essential/sort" size="sm" />
        {{ sortLabel }}
        <ds-icon button-icon-end name="arrow/arrow-down-02" size="sm" />
      </button>
    </ng-container>
  </app-table-toolbar>

  <app-filter-bar table-toolbar appearance="inline" ariaLabel="الفلاتر المطبقة"
    [applied]="appliedFilters" [resultCount]="resultCount" [resultNoun]="articleNoun"
    (removed)="removeFacet($event)" (cleared)="clearPanelFilters()" />

  <table>
    …
    <tbody>
      @if (articles.length === 0) {
        <tr><td colspan="8" class="ds-page__state-cell">
          <app-empty-state variant="no-results" illustration="art"
            title="لا توجد مقالات مطابقة" description="جرب إزالة أحد الفلاتر أو تغيير كلمة البحث.">
            <img empty-illustration src="assets/illustrations/no-results.svg" alt="" />
            <div empty-actions class="articles-no-results">
              @for (filter of appliedFilters; track filter.key) {
                <button dsButton type="button" variant="secondary" size="sm" (click)="removeFacet(filter.key)">
                  <ds-icon button-icon name="essential/close-circle" size="sm" />
                  إزالة فلتر {{ filter.label }}
                </button>
              }
            </div>
          </app-empty-state>
        </td></tr>
      }
    </tbody>
  </table>
</app-table>
```

و`resultCount` في الشاشة `null` إلا مع شرط مطبَّق ونتائج وبعد التحميل. (وُثّق 2026-09-26 من الكود)

## 12. ممنوع

* ❌ تبويبات تؤدي وظيفة فلتر.
* ❌ مربّع اختيار يَعِد بتعدّد لا يقبله الخادم.
* ❌ الترتيب رقاقةَ فلتر أو داخل لوحة الفلترة.
* ❌ فلتر مطبَّق غير مرئي خارج اللوحة.
* ❌ تصفية الصفحة المحمَّلة وحدها فوق جدول مرقَّم من الخادم.
* ❌ عدّاد مختلَق — صفر مكان المجهول، أو عددٌ من الصفحة المحمَّلة.
* ❌ زرّ «تطبيق» فوق اختيار يسري فورًا.
* ❌ إخفاء الشريط أو الرقائق في حالة «لا نتائج».
